# Поддержка ключевых бизнес-сценариев целевой архитектурой

## 1. Быстрая подготовка отчётности

### Компоненты архитектуры, поддерживающие сценарий:

**Цепочка быстрой отчётности:**
```
Бизнес-пользователь → Портал самообслуживания → BI/Конструктор отчётов → 
Semantic/Metric Layer → Enterprise Data Lakehouse (VITRINES) → Отчёт готов
```

**Ключевые компоненты:**

1. **Портал самообслуживания (Витрина данных)**
   - Прямой доступ бизнес-пользователей к данным
   - Не требует обращения в IT-отдел
   - Self-service интерфейс

2. **BI / Конструктор отчётов (Ad-hoc, дашборды)**
   - Возможность создания отчётов без знания SQL
   - Готовые шаблоны дашбордов
   - Интерактивная визуализация

3. **Semantic / Metric Layer (Единые метрики KPI)**
   - Предрасчитанные метрики и KPI
   - Единый словарь данных
   - Исключает необходимость сложных вычислений

4. **Enterprise Data Lakehouse (RAW / CURATED / VITRINES)**
   - Слой VITRINES содержит предварительно агрегированные данные
   - Оптимизированные витрины для быстрых запросов
   - Партиционирование и индексация

5. **Data Catalog & Governance**
   - Быстрый поиск нужных данных
   - Понимание происхождения данных (lineage)
   - Метаданные для самообслуживания

**Результат:** Время формирования отчётов снижается с часов до минут/секунд за счёт предрасчитанных витрин и самообслуживания.

## 2. Независимое развитие финтех- и ИИ-направлений

### Компоненты архитектуры, поддерживающие сценарий:

**Доменная изоляция:**
```
Домен: Финтех/Банк (независимый)
  ├── Core Banking / Fintech Services (Java/Golang)
  ├── Fintech Data Product (Доменные витрины)
  └── События → Event Bus → Data Lakehouse

Домен: AI-сервисы (независимый)
  ├── AI Services (Python)
  ├── AI Ops Data Product (Опер. метрики)
  └── События → Event Bus → Data Lakehouse
```

**Ключевые компоненты:**

1. **Доменная структура**
   - Каждый домен (Финтех, AI, Клиники, Головной офис) изолирован
   - Собственные Data Products для каждого домена
   - Независимое развитие технологий (Java/Golang для финтех, Python для AI)

2. **Event Bus / Streaming (pub/sub)**
   - Асинхронная интеграция через события
   - Слабая связанность между доменами
   - Изменения в одном домене не требуют изменений в других

3. **Fintech Data Product / AI Ops Data Product**
   - Каждый домен предоставляет свои данные как готовый продукт
   - Стандартизированный интерфейс доступа
   - Доменные витрины независимы друг от друга

4. **ETL/Orchestration**
   - Каждый домен может иметь свои пайплайны
   - Независимое расписание и CI/CD
   - Изоляция процессов обработки данных

**Результат:** Финтех и AI направления могут развиваться независимо, добавлять новые функции и масштабироваться без влияния друг на друга.

## 3. Масштабирование для новых бизнесов

### Компоненты архитектуры, поддерживающие сценарий:

**Архитектура для масштабирования:**
```
Новый бизнес → Новый домен → Data Product → Event Bus → Data Lakehouse
                                    ↓
                            Портал самообслуживания
```

**Ключевые компоненты:**

1. **Доменная архитектура (мульти-доменная платформа)**
   - Легко добавлять новые домены (например, фармацевтические компании, производитель оборудования)
   - Каждый новый бизнес = новый домен
   - Изоляция от существующих доменов

2. **Event Bus / Streaming**
   - Стандартизированный способ интеграции новых направлений
   - Не требует изменений в существующих системах
   - Поддержка pub/sub для любых новых источников данных

3. **Self-Serve Data Platform (компоненты платформы)**
   - **Data Catalog**: автоматически индексирует новые источники
   - **ETL/Orchestration**: единая платформа для всех доменов
   - **Data Quality**: стандартизированные проверки для новых данных
   - **IAM/SSO**: единая система доступа для всех направлений

4. **Enterprise Data Lakehouse**
   - Масштабируемое хранилище (облако)
   - Поддержка любых объёмов данных
   - Горизонтальное масштабирование

5. **Портал самообслуживания**
   - Автоматически получает доступ к новым доменам через Data Catalog
   - Бизнес-пользователи могут сразу работать с данными новых направлений
   - Не требует изменений в портале при добавлении доменов

**Результат:** Новые бизнес-направления (фармацевтические компании, производитель оборудования) интегрируются быстро и без изменения существующей архитектуры.

## Визуальное отображение на диаграмме

### Аннотации для диаграммы:

1. **Быстрая отчётность** (зелёная пунктирная линия):
   - Портал → BI → Semantic → Lakehouse (VITRINES)

2. **Независимое развитие** (синяя/жёлтая рамка):
   - Домен Финтех (синий)
   - Домен AI (жёлтый)
   - Event Bus между ними

3. **Масштабирование** (пунктирная рамка):
   - Вся платформа с пометкой "Легко добавлять новые домены"
   - Event Bus с пометкой "Стандартизированная интеграция"

## Связь с целями бизнеса

| Бизнес-сценарий | Влияние на бизнес | Ключевые компоненты |
|----------------|-------------------|---------------------|
| **Быстрая подготовка отчётности** | Критично для выручки: ускорение принятия управленческих решений | Портал, BI, Semantic Layer, Data Lakehouse (VITRINES) |
| **Независимое развитие направлений** | Критично для time-to-market: ускорение вывода новых продуктов | Доменная архитектура, Event Bus, Data Products |
