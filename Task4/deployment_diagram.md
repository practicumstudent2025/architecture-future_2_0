# Диаграмма автоматизации развёртывания инфраструктуры "Будущее 2.0"

## Компонентная схема инфраструктуры

### Управляется Terraform (Infrastructure as Code)

#### Сетевая инфраструктура
- **VPC Network** (`future-2-0-network`) - основная виртуальная сеть
- **Public Subnet** (10.0.1.0/24) - публичная подсеть для доступа из интернета
- **Private Fintech Subnet** (10.0.2.0/24) - приватная подсеть для финтех домена
- **Private AI Subnet** (10.0.3.0/24) - приватная подсеть для AI домена
- **Private Medical Subnet** (10.0.4.0/24) - приватная подсеть для медицинского домена
- **Private Data Subnet** (10.0.5.0/24) - приватная подсеть для данных
- **NAT Gateway** - шлюз для доступа в интернет из приватных подсетей
- **Route Table** - таблица маршрутизации для приватных подсетей
- **Security Groups** - группы безопасности для публичных и приватных ресурсов

#### Вычислительные ресурсы (VM)
- **Bastion Host** (2 cores, 4 GB) - хост для доступа к приватным сетям
- **Data Lakehouse VM** (8 cores, 32 GB) - виртуальная машина для Data Lakehouse
- **Event Bus (Kafka) VM** (4 cores, 16 GB) - виртуальная машина для Kafka
- **Data Catalog VM** (4 cores, 16 GB) - виртуальная машина для Data Catalog
- **Fintech Domain VM** (4 cores, 16 GB) - виртуальная машина для финтех домена
- **AI Domain VM** (8 cores, 32 GB) - виртуальная машина для AI домена
- **BI Portal VM** (4 cores, 16 GB) - виртуальная машина для портала самообслуживания

#### Диски
- **Data Lakehouse Disk** (500 GB SSD) - диск для данных Data Lakehouse
- **Fintech Data Disk** (200 GB SSD) - диск для данных финтех домена
- **AI Data Disk** (300 GB SSD) - диск для данных AI домена

### Разворачивается вручную (Post-Terraform)

#### Приложения и сервисы
- **Kafka Installation** - установка и настройка Apache Kafka на Event Bus VM
- **Data Catalog Setup** - установка и настройка Data Catalog (например, DataHub) на Data Catalog VM
- **BI Portal Setup** - установка и настройка портала самообслуживания на BI Portal VM
- **Application Configuration** - настройка приложений:
  - IAM/SSO интеграция
  - Мониторинг и логирование
  - Конфигурация доменных приложений (Fintech, AI, Medical)
  - Настройка Data Lakehouse (Iceberg, Delta Lake)
  - Настройка ETL/ELT пайплайнов

#### Интеграции
- Настройка интеграции между доменами через Event Bus
- Настройка доступа к Data Catalog из BI Portal
- Настройка синхронизации данных между доменами

## Обоснование разделения

### Почему инфраструктура управляется Terraform?

1. **Воспроизводимость**: Инфраструктура может быть развёрнута идентично в любой среде (dev, staging, prod)
2. **Версионирование**: Изменения инфраструктуры отслеживаются в Git
3. **Безопасность**: Минимизация человеческих ошибок при развёртывании
4. **Масштабируемость**: Легко добавить новые VM, подсети, диски
5. **Документация**: Код инфраструктуры является самодокументируемым

### Почему приложения разворачиваются вручную?

1. **Гибкость конфигурации**: Приложения требуют специфичной настройки под бизнес-требования
2. **Зависимости**: Приложения зависят от внешних сервисов (IAM, мониторинг)
3. **Итеративная настройка**: Требуется тестирование и доработка конфигурации
4. **Специфичные требования**: Каждое приложение имеет уникальные требования к настройке

## Процесс развёртывания

1. **Этап 1: Terraform Apply**
   - Создание VPC, подсетей, NAT Gateway
   - Создание Security Groups
   - Создание дисков
   - Создание виртуальных машин
   - Настройка сетевых подключений

2. **Этап 2: Подготовка VM**
   - Подключение к VM через Bastion Host
   - Установка базового ПО (Docker, Kubernetes, если требуется)
   - Настройка системных параметров

3. **Этап 3: Установка приложений**
   - Установка Kafka на Event Bus VM
   - Установка Data Catalog на Data Catalog VM
   - Установка BI Portal на BI Portal VM
   - Настройка Data Lakehouse на Data Lakehouse VM

4. **Этап 4: Конфигурация**
   - Настройка интеграций между компонентами
   - Настройка IAM/SSO
   - Настройка мониторинга
   - Настройка доменных приложений
