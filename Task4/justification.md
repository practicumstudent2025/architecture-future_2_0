# Обоснование конфигурации инфраструктуры

## Выбор провайдера

Выбран **Yandex Cloud** как облачный провайдер для компании "Будущее 2.0" по следующим причинам:
- Соответствие требованиям локализации данных (важно для медицинских и финансовых данных)
- Наличие всех необходимых сервисов (Compute, VPC, Storage)
- Конкурентные цены
- Хорошая документация и поддержка Terraform

## Архитектура сети

### VPC и подсети

Создана единая VPC с разделением на публичную и приватные подсети:
- **Публичная подсеть (10.0.1.0/24)**: Для bastion host и BI Portal с прямым доступом в интернет
- **Приватные подсети**:
  - Финтех домен (10.0.2.0/24) - изоляция финансовых данных
  - AI домен (10.0.3.0/24) - изоляция AI сервисов
  - Медицинский домен (10.0.4.0/24) - изоляция медицинских данных (для будущего расширения)
  - Data подсеть (10.0.5.0/24) - для Data Lakehouse, Event Bus, Data Catalog

### NAT Gateway

Использован NAT Gateway для обеспечения доступа в интернет из приватных подсетей без прямого доступа извне. Это обеспечивает:
- **Безопасность**: Приватные VM не имеют публичных IP
- **Экономию**: Один NAT Gateway для всех приватных подсетей
- **Масштабируемость**: Автоматическое масштабирование трафика

## Виртуальные машины

### Bastion Host
- **Ресурсы**: 2 cores, 4 GB RAM
- **Назначение**: Единая точка доступа к приватным сетям
- **Обоснование**: Минимальные ресурсы, так как используется только для SSH туннелирования

### Data Lakehouse
- **Ресурсы**: 8 cores, 32 GB RAM
- **Диск**: 500 GB network-ssd
- **Назначение**: Хранение и обработка данных (RAW/CURATED/VITRINES слои)
- **Обоснование**: Высокие ресурсы необходимы для обработки сотен терабайт данных и выполнения сложных трансформаций

### Event Bus (Kafka)
- **Ресурсы**: 4 cores, 16 GB RAM
- **Назначение**: Асинхронная интеграция между доменами
- **Обоснование**: Средние ресурсы достаточны для обработки событий, при необходимости можно масштабировать горизонтально

### Data Catalog
- **Ресурсы**: 4 cores, 16 GB RAM
- **Назначение**: Каталог данных с lineage
- **Обоснование**: Достаточно для метаданных и поиска, не требует больших ресурсов

### Финтех домен
- **Ресурсы**: 4 cores, 16 GB RAM
- **Диск**: 200 GB network-ssd
- **Назначение**: Финтех-сервисы на Golang и Java
- **Обоснование**: Средние ресурсы для банковских сервисов, отдельный диск для изоляции данных

### AI домен
- **Ресурсы**: 8 cores, 32 GB RAM
- **Диск**: 300 GB network-ssd
- **Назначение**: ИИ-сервисы на Python для работы с медицинскими данными
- **Обоснование**: Высокие ресурсы необходимы для ML моделей и обработки медицинских данных

### BI Portal
- **Ресурсы**: 4 cores, 16 GB RAM
- **Назначение**: Портал самообслуживания для бизнес-пользователей
- **Обоснование**: Средние ресурсы достаточны для веб-приложения, публичный доступ для пользователей

## Диски

### Тип дисков: network-ssd
- **Обоснование**: Высокая производительность необходима для:
  - Быстрой загрузки данных в Data Lakehouse
  - Обработки больших объёмов данных
  - Низкой задержки для AI вычислений

### Размеры дисков
- **Data Lakehouse**: 500 GB - для хранения RAW/CURATED/VITRINES слоёв
- **Финтех**: 200 GB - для финансовых данных домена
- **AI**: 300 GB - для моделей и обработанных данных

## Security Groups

### Публичная Security Group
- Разрешён SSH (22), HTTP (80), HTTPS (443) из интернета
- Полный исходящий трафик

### Приватная Security Group
- Разрешён трафик внутри security group (между VM)
- Разрешён Kafka (9092) и Data Catalog (8080) из внутренней сети
- Полный исходящий трафик через NAT

## Infrastructure as Code (IaC)

### Преимущества декларативного подхода

1. **Воспроизводимость**
   - Одинаковая инфраструктура в dev/staging/prod
   - Легко восстановить после сбоя
   - Версионирование конфигурации в Git

2. **Масштабируемость**
   - Легко добавить новые VM или домены
   - Изменение ресурсов через переменные
   - Автоматическое создание инфраструктуры для новых окружений

3. **Безопасность**
   - Контроль изменений через code review
   - Документирование инфраструктуры в коде
   - Исключение ручных ошибок

4. **Эффективность**
   - Автоматизация развёртывания
   - Быстрое создание тестовых окружений
   - Упрощение управления инфраструктурой

### Компоненты, управляемые Terraform

- ✅ VPC и подсети
- ✅ NAT Gateway и routing
- ✅ Security Groups
- ✅ Виртуальные машины
- ✅ Диски

### Компоненты, разворачиваемые вручную

- ⚙️ Установка и настройка ПО на VM (Kafka, Data Catalog, BI Portal)
- ⚙️ Конфигурация приложений
- ⚙️ Настройка мониторинга и логирования
- ⚙️ Настройка IAM/SSO (используется внешний сервис)
- ⚙️ Резервное копирование (настраивается отдельно)

## Масштабирование

Инфраструктура спроектирована с учётом масштабирования:
- Легко добавить новые VM через копирование ресурсов
- Увеличение ресурсов через изменение переменных
- Горизонтальное масштабирование Kafka через добавление брокеров
- Увеличение дисков без остановки сервисов
