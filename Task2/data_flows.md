# Потоки данных для бизнес-сценариев

## Бизнес-сценарий 1: Интеграция нового финтех-сервиса

**Поток данных:**
```
Финтех домен → Финансовые данные → Data Lakehouse (VITRINES) → 
Аналитический домен → Бизнес-пользователи
```
Альтернативный поток через события:
```
Финтех домен → Event Bus → Data Lakehouse (RAW) → 
Аналитический домен → Бизнес-пользователи
```

**Преимущества доменной архитектуры:**
- Новый финтех-сервис добавляется в Финтех домен без изменения других доменов
- События публикуются в Event Bus, другие домены подписываются при необходимости
- Витрины создаются независимо в рамках домена

## Бизнес-сценарий 2: Использование ИИ для анализа медицинских данных

**Поток данных:**
```
Медицинский домен → Медицинские данные (изолированы) → AI домен (обработка) → 
Event Bus → Data Lakehouse (агрегаты) → Аналитический домен
```
Параллельно:
```
Медицинский домен → Event Bus → Data Lakehouse (RAW)
```

**Важно:** Медицинские карты и истории не попадают в аналитический домен, только агрегированные метрики.

**Преимущества доменной архитектуры:**
- AI домен изолирован, может развивать свои алгоритмы независимо
- Медицинские данные остаются в медицинском домене
- Аналитика получает только операционные метрики

## Бизнес-сценарий 3: Интеграция фармацевтической компании

**Поток данных:**
```
Новый домен (Фармацевтика) → Event Bus → Data Lakehouse → 
Аналитический домен → Бизнес-пользователи
```

**Преимущества доменной архитектуры:**
- Новый домен добавляется без изменения существующих
- Стандартизированная интеграция через Event Bus
- Автоматическое появление в портале через Data Catalog
