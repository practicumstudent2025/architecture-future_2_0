# Потоки данных для бизнес-сценариев

## 1. Интеграция нового финтех-сервиса

Когда нужно добавить новый финтех-сервис, данные могут идти двумя путями:

Основной поток:
```
Финтех домен → Финансовые данные → Data Lakehouse (VITRINES) → 
Аналитический домен → Бизнес-пользователи
```

Или через события (для real-time обработки):
```
Финтех домен → Event Bus → Data Lakehouse (RAW) → 
Аналитический домен → Бизнес-пользователи
```

Главное преимущество — новый сервис добавляется только в Финтех домен, остальные домены не трогаем. События уходят в Event Bus, кто нужно — подписывается. Витрины создаём сами, независимо от других.

## 2. Использование ИИ для анализа медицинских данных

Здесь важно, что медицинские карты и истории болезней не попадают в аналитику — только агрегированные метрики.

Поток данных:
```
Медицинский домен → Медицинские данные (изолированы) → AI домен (обработка) → 
Event Bus → Data Lakehouse (агрегаты) → Аналитический домен
```

Параллельно идут сырые события:
```
Медицинский домен → Event Bus → Data Lakehouse (RAW)
```

AI домен работает изолированно, может развивать алгоритмы без влияния на другие части системы. Медицинские данные остаются в своём домене, в аналитику попадают только операционные метрики.

## 3. Интеграция фармацевтической компании

Когда добавляем новый бизнес (например, фармацевтику), поток простой:

```
Новый домен (Фармацевтика) → Event Bus → Data Lakehouse → 
Аналитический домен → Бизнес-пользователи
```

Новый домен добавляется без изменения существующих. Интеграция стандартная через Event Bus, данные автоматически появляются в портале через Data Catalog.
